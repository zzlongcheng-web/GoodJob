# Golden Gain CRM 生产上线验收单（发布候选版）

> 状态：待真实业务环境验收签字。CI 成功不能代替员工、真实 WhatsApp 设备、真实发信域名和数据库恢复演练。禁止把这一文件视为部署许可。

## 一、版本与安全门禁

- [ ] 对照 GitHub 固定 SHA，源码/lockfile/Dockerfile/镜像 tag 一致，禁止直接使用浮动 latest 标签。
- [ ] GitHub CI `Build and self-tests`、`MySQL integration tests` 都成功；取消、跳过不得冒充通过。
- [ ] Trivy 扫描 backend、communication、gateway、mysql 生产镜像：Critical=0、High=0；扫描结果 ZIP 保留。
- [ ] npm audit root/backend 与 WhatsApp plugin 生产依赖 Critical=0、High=0；Moderate 单独列出并由风险负责人签署处置方式。
- [ ] SheetJS 官方发行包使用 `https://cdn.sheetjs.com/xlsx-0.20.3/xlsx-0.20.3.tgz`，SHA-512 lock 校验完整；构建失败时禁止自动使用旧版。
- [ ] 生产环境 `CRM_STORE=mysql`、`APP_DATABASE_PROFILE=production`、`CRM_SEED_DEVELOPMENT_DATA=false`。
- [ ] 只允许公司自有初始管理员邮箱，禁止默认演示管理员；启用 MFA、更换所有默认密码，实际使用强口令和 secrets 文件。
- [ ] HTTPS、JWT、Cookie Secure、CORS、反向代理可信跳数、CSRF、密钥轮换、日志脱敏和限速核实。
- [ ] 发布工件的 SHA256、镜像 digest、回滚镜像 digest 已归档。

## 二、MySQL 及数据安全

- [ ] 在目标 MySQL 8.4 数据库跑初装迁移和从旧版升级迁移，分别检查行数、索引、外键、重复客户、权限数据完整。
- [ ] `@@log_bin=OFF` 与 Docker 生产配置一致（测试库配置不代替生产配置）。
- [ ] 建立加密数据库备份，记录恢复点 RPO 与恢复时间 RTO；必须实际把备份恢复到独立实例并抽样比对客户、WhatsApp 记录、绩效数据。
- [ ] 停机升级/不停机升级各有完整回滚说明；恢复演练不触碰在线正式数据。
- [ ] 客户、跟进记录、WhatsApp 附件、订单文件的持久化卷、容量预警及保留策略核实。

## 三、员工角色与 WhatsApp 隔离（真实环境，需双账号）

- [ ] 使用同一部门两名业务员 A、B 和跨部门 C：A 只能看到授权客户和其对话，不得读取、搜索、同步或导出 B/C 私有记录。
- [ ] 验证直接调用旧 API、分页接口、WebSocket、下载附件链接同样不越权；必须返回 403 或 404。
- [ ] 普通业务员不允许删除自己或他人的客户、WhatsApp 消息和客户沟通记录，批量删除及旧接口也拒绝。
- [ ] 管理员按审批权限查询团队报表，保持审计追踪，管理员误操作可以回滚。
- [ ] 真正绑定员工 WhatsApp/企业 WhatsApp 账户，完成发送、接收、媒体、断线重连、会话重同步、消息去重；核实没有误发到客户的自动消息。
- [ ] 下线一个员工，验证会话凭证失效、历史客户转交和活动审计。

## 四、61 家新客户月度绩效（Asia/Shanghai）

- [ ] 每位业务员单月目标为 61 家，不同导入记录但同一个客户只计一次。
- [ ] 仅有发出消息或仅有客户回复不能计入“已核实 WhatsApp 双向有效沟通”；至少要同客户双向通信。
- [ ] 电话、邮件、会议和手工填写记录须经主管审核，未审核不得计入“已独立核实”数量。
- [ ] 月末 23:59:59 与次月 00:00:00（北京时间）各生成 1 笔证据，核对跨 UTC 日期的归属。
- [ ] 报表管理员/主管访问范围和员工自查权限分别验收，不能看见跨部门绩效。
- [ ] 对历史客户、无效线索、回收公海客户、重复记录和未来时间戳做回归。

## 五、外贸业务及第三方接口

- [ ] 用真实但可公开的测试订单验证 PI/报价单/采购合同/装箱单/报关单生成、导入、导出和 PDF 中英文排版。
- [ ] 使用纸质签章、产品图片、长表格（12 条/80 条）测试 Excel 预览/导出哈希及完整性；修改模板不丢业务字段。
- [ ] 验证国家分配、重复客户归属、每周六美东时间 09:00 搜客计划与人工国家设置；遵循外部服务使用条款与配额。
- [ ] 验证国际电话服务商的外拨回调与记录（真实提供商沙箱），失败或重复回调不能产生假通话。
- [ ] 验证 SMTP/IMAP 实际授权发信、DKIM/SPF/DMARC、退信、速率限制、邮件跟踪与退订；使用测试域名/收件人。
- [ ] 假设一个外部接口不可用，验证 CRM 不泄露口令、不会自动重试发送重复消息，降级行为可见。

## 六、灰度上线与批准

- [ ] 生产配置审核（基础镜像/数据库/服务端口/环境变量/secrets）及供应商对接人签字。
- [ ] 先 2 名测试员工，再 5–15 名灰度员工，验证权限、性能、CPU/内存/存储、操作审计和用户满意度。
- [ ] 关键监控、备份告警、消息队列堆积和故障联系人员已完成交接。
- [ ] 产品负责人、技术负责人、安全负责人、数据负责人在验收报告记录真实日期、签名及部署目标。
- [ ] 未经上述签署，PR 保持 Draft，不自动合并到 master、不断言“正式生产可用”。

验收时请把工单编号、实际截图或日志链接、结果及责任人加到每项旁边，不能仅把复选框勾上。
